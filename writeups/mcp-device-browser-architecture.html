Designing Sandboxed Model Context Protocol (MCP) Bridges for Android ADB & Headless Browser E2E Verification

Author: Fata Fatikhul Karim • Repository: android-browser-mcp

1. Context & Threat Model

Connecting an LLM agent to physical Android hardware (via ADB) and headless Chromium (via Chrome DevTools Protocol) enables automated End-to-End (E2E) UI verification. However, bridging an LLM to OS-level tools introduces a critical threat vector: Indirect Prompt Injection leading to Command Injection when parsing untrusted DOM or UI accessibility text. 

[LLM Client] ⇄ (JSON-RPC 2.0 stdio) ⇄ [Node.js MCP Server (Schema Guardrails)]
                                             ├──► Android ADB Module (XML UI Tree Parser)
                                             └──► Chromium CDP Module (Isolated Context)

2. Root Cause of Naive Bridge Vulnerabilities

Naive ADB wrappers concatenate LLM-supplied strings directly into shell commands (child_process.exec), allowing metacharacters (;, $(), backticks) in UI labels or form inputs to execute arbitrary shell commands on the host: 

// ❌ VULNERABLE: String interpolation in shell execution
function unsafeAdbInput(userText) {
  // If userText contains `"; rm -rf / #`, the host shell executes it!
  exec(`adb shell input text "${userText}"`);
}

3. Architectural Trade-Offs & Security Guardrails

  • Accessibility Tree Resolution vs. Pixel Coordinates: Instead of hardcoded X/Y coordinates that break across screen densities, the bridge parses uiautomator dump XML nodes and computes bounding-box centroids dynamically.
  • Parameterized Subprocess Execution: All ADB calls use execFile('adb', argsArray) without invoking a shell interpreter, neutralizing host-side command injection.
  • Strict Input Allowlisting: Package names, coordinates, and keycodes are validated against strict regular expressions before dispatch.

4. Patched Implementation & Verification

// ✅ SAFE: Parameterized execFile + strict coordinate & package validation
import { execFile } from 'node:child_process';
import { promisify } from 'node:util';
const execFileAsync = promisify(execFile);

const PACKAGE_REGEX = /^[a-zA-Z][a-zA-Z0-9_]*(\.[a-zA-Z0-9_]+)+$/;

export async function safeOpenApp(targetSerial, packageName) {
  if (!PACKAGE_REGEX.test(packageName)) {
    throw new Error('Invalid Android package identifier rejected by guardrail');
  }
  const args = targetSerial ? ['-s', targetSerial, 'shell', 'monkey', '-p', packageName, '1']
                            : ['shell', 'monkey', '-p', packageName, '1'];
  return await execFileAsync('adb', args, { timeout: 8000 });
}
