Multi-Source Passive Subdomain Enumeration & Non-Destructive API Boundary Auditing in Python

Author: Fata Fatikhul Karim • Repository: fata-termux-toolkit (Fata Recon Suite v3.0) • Verification: 5 Automated Unit Tests (tests/test_recon.py)

1. Problem Statement & Design Constraints

Pre-release security hygiene checks often fail in constrained CI runners or lightweight Linux containers due to heavy third-party dependency trees or single-source OSINT timeouts (such as crt.sh PostgreSQL query locks on large domains).

2. Multi-Source Passive OSINT Failover

To achieve deterministic reliability with zero external dependencies, recon.py uses Python's standard library (urllib.request, ssl, concurrent.futures) to aggregate passive DNS records across three independent sources:

  • Primary: AlienVault OTX Passive DNS JSON API (low-latency historical DNS).
  • Secondary: HackerTarget HostSearch API.
  • Tertiary Fallback: Certificate Transparency logs via crt.sh.

3. Non-Destructive API Boundary Probing & Authorization Guardrail

Inspired by real-world business-logic findings where negative or zero numeric inputs caused unhandled exceptions or solver hangs, Module 5 (--fuzz) sends five non-destructive boundary probes (0, -500, 1e308, null, '"<>) and compares HTTP status codes and response latency against a baseline request. Active boundary probing is disabled by default unless the operator passes the explicit --confirm-authorized flag.

4. Automated Unit Testing & GitHub Actions CI

Every commit is verified via GitHub Actions (.github/workflows/ci.yml) running the automated unittest suite (tests/test_recon.py): 

python3 -m unittest discover -s tests -v
